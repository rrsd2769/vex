# Devlog

One paragraph per working day: **what broke, why, how you fixed it.**

Not a progress report — a bug journal. Progress is visible in git; the
reasoning behind a fix is not, and that is the part you will need when
someone asks "tell me about a difficult bug you debugged."

Write the entry when the bug is fresh. You will not remember it in a week.

---

## Template

```
### YYYY-MM-DD
**Symptom:**  what I saw go wrong
**Cause:**    what was actually wrong
**Fix:**      what I changed
**Learned:**  the thing I did not know before
```
